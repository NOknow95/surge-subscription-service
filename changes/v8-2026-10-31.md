# v8-2026-10-31 拉取失败时显示错误原因链

## 目的

排查上游拉取失败时，`fetch` 只暴露笼统的 `fetch failed`，看不出是 DNS、连接被重置、TLS 失败还是超时。把底层原因一并记录，便于直接判断问题出在哪一层。

## 主要改动

- 新增 `describeError`：沿 `error.cause` 链最多取 4 层，拼接 `code`（如 `ECONNREFUSED`、`ECONNRESET`）与 message，去掉重复项，超过 300 字符截断。
- 拉取失败时，该文案同时写入 Profile 的 `lastError`、`/api/profiles/:id/refresh` 返回值与无缓存情况的 502 响应体，管理页提示、`/api/state` 和 `state.json` 中看到的内容一致。
- 已有明确文案的失败（如 `上游返回 HTTP 503`、`上游配置超过 15 MB`、脚本错误）不含 cause，文案保持原样，不影响既有接口语义。
- 只读或非对象抛出值无法写入 message 时静默跳过，不改变原有失败处理流程。

示例文案：

- `fetch failed <- connect ECONNREFUSED 127.0.0.1:45999`
- `fetch failed <- read ECONNRESET`
- `fetch failed <- ETIMEDOUT`

## 迁移影响

无。`lastError` 仍是字符串，只是内容更详细；旧的 `lastError` 值在下次拉取前保持原样。

## 验证

- `node --check src/server.js`、`node --check public/app.js` 通过。
- `npm test` 全部通过，新增断言：上游指向关闭端口时 `lastError` 以 `fetch failed` 开头且包含 `ECONNREFUSED`，`stale` 为 `true`，且 `/api/state` 与 refresh 返回值一致。
- 手动验证三类失败，分别得到 `fetch failed <- connect ECONNREFUSED 127.0.0.1:<port>`、`fetch failed <- ECONNRESET: Client network socket disconnected before secure TLS connection was established` 与 `fetch failed <- bad port`，确认 cause 链会被拼接且长文本会被截断。
