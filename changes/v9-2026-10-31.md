# v9-2026-10-31 上游拉取支持走代理

## 目的

部署机器的网络可能到不了上游订阅域名（按域名/SNI 阻断、连接被重置或直接丢包）。此前这种情况只能在页面看到 `fetch failed`，无法通过服务自身绕开。本次让「拉取上游配置」这一步可以走本地 HTTP 代理，其余行为不变。

## 主要改动

- 采用 Node 内置的环境变量代理支持（`NODE_USE_ENV_PROXY` / `--use-env-proxy` → undici `EnvHttpProxyAgent`），不新增任何依赖，也不改服务端代码。
- `compose.yaml` 新增环境变量：
  - `NODE_USE_ENV_PROXY: "1"`：启用上述支持；
  - `HTTPS_PROXY` / `HTTP_PROXY`：默认空，为空时行为与直连完全一致；
  - `NO_PROXY`：默认 `localhost,127.0.0.1`，命中的上游不走代理；
  - `extra_hosts: host.docker.internal:host-gateway`：代理跑在宿主机上时可以用 `host.docker.internal` 访问，不必写死局域网 IP。
- 代理只作用于拉取上游这一步；管理页、配置生成与输出给 Surge 的内容都不经过代理。
- 支持带账号密码的代理地址（`http://user:pass@host:port`）；代理协议为 HTTP（CONNECT 隧道），只有 SOCKS 代理时需先用 clash/mihomo 的 `mixed-port` 或 gost 转成 HTTP。
- `README.md` / `README.en.md` 补充三个环境变量、新增「上游拉取走代理」小节，并在故障排查表增加 `ECONNRESET` / `ETIMEDOUT` 的处理指引。
- 测试：`startService` 支持传入额外环境变量；新增两个用例——设置代理后上游确实经代理拉取（断言代理收到的 CONNECT 目标与返回内容），以及 `NO_PROXY` 命中的上游直连、代理收不到任何请求。

## 配置与迁移影响

- 不配置 `HTTPS_PROXY` / `HTTP_PROXY` 时行为不变，无需迁移。
- 代理变量必须通过进程环境变量传入（Node 在进程启动时读取），不能运行期修改。
- `--use-env-proxy` / `NODE_USE_ENV_PROXY` 只在较新的 Node 22.x 上存在（v22.19.0 没有，v22.23.3 有）；旧版本会忽略这些变量，表现为直连。
- 代理在宿主机上时，容器需用 `host.docker.internal`（配 `host-gateway`）或宿主机地址访问；容器内的 `127.0.0.1` 不是宿主机。
- 代理协议为 HTTP 代理的 CONNECT 隧道，对 `http://` 与 `https://` 目标都适用；只有 SOCKS 代理时需先转成 HTTP。
- 启用后启动日志多一行 `[UNDICI-EHPA] Warning: EnvHttpProxyAgent is experimental`，仅为提示。

## 验证

- `npm test`：在支持 env 代理的 Node 上 24 项全部通过（含两个代理用例）；不支持该开关的旧版本会自动跳过这两个用例，其余 22 项通过。
- 手工验证：`NODE_USE_ENV_PROXY=1` 且 `HTTPS_PROXY` 指向关闭端口时错误为 `connect ECONNREFUSED 127.0.0.1:<port>`，说明请求确实走了代理；使用 `NO_PROXY` 后恢复直连。
- 测试实现依据：env 代理对 `http://` 目标同样使用 CONNECT 隧道，因此用例用最小 CONNECT 代理模拟上游，并断言代理收到的 CONNECT 目标与返回内容。
