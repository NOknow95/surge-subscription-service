Surge 转换脚本编写指南

用 JavaScript 按顺序修改上游 Surge 配置。脚本以配置对象为输入并返回处理后的对象；服务再把结果序列化为完整 Surge 配置。

1. 执行流程

  1. Surge 请求服务的 /subscription 链接时，服务重新拉取上游完整配置。
  2. 服务解析配置分节，并把每个分节的非空行整理为行数组；注释会保留。
  3. 服务按管理页显示顺序运行所有已启用脚本。下一段脚本收到上一段脚本返回的配置。
  4. 服务把结果写成完整 Surge 配置，在开头加入指向服务订阅链接的 #!MANAGED-CONFIG 行并返回给 Surge。

禁用脚本会跳过。调整脚本顺序会改变执行顺序；如果一个脚本改写了规则，后面的脚本看到的就是改写后的规则。

2. 可用配置对象

脚本接收一个 config 对象。可以直接用分节名读取或修改对应的行数组：

字段含义示例
config['General']直接访问对应分节的字符串数组。config 本身就是以分节名为键的对象。数组中的每一项对应一条非空配置行；注释会保留，空行会过滤。分节不存在时可先赋空数组创建。config['General'].push('loglevel = notify')
config.rules[Rule] 分节的快捷入口，与 config['Rule'] 指向同一数组。给它赋新数组也会替换 Rule 分节内容。config.rules.unshift('FINAL,DIRECT')

分节名称区分大小写。使用 config['Rule'] 表示配置中的 [Rule]，使用 config['Proxy Group'] 表示 [Proxy Group]。

3. 最小脚本模板

module.exports = (config) => {
  // 在这里读取或修改 config['General'] / config.rules

  return config;
};

脚本必须通过 module.exports 导出函数，并返回配置对象。即使只检查配置、不做修改，也要返回 config。

4. 常用操作示例

4.1 在现有规则前添加规则

新规则先匹配，因此要确认它们不会遮蔽上游中更具体的规则。

module.exports = (config) => {
  config.rules = [
    'DOMAIN,registry.hub.docker.com,节点选择',
    'DOMAIN,registry-1.docker.io,节点选择',
    'DOMAIN,auth.docker.io,节点选择',
    'DOMAIN-SUFFIX,docker.io,节点选择',
    'DOMAIN-SUFFIX,docker.com,节点选择',
    ...(config.rules || []),
  ];
  return config;
};

4.2 在规则末尾追加规则

末尾追加的规则排在上游规则之后。若已有 FINAL 规则，放在它后面的规则通常不会被匹配；需要优先应用的规则应放在 FINAL 前面。

module.exports = (config) => {
  config.rules.push('DOMAIN-SUFFIX,example.org,DIRECT');
  return config;
};

4.3 把规则插入到 FINAL 前

module.exports = (config) => {
  const rule = 'DOMAIN-SUFFIX,example.org,DIRECT';
  const finalIndex = config.rules.findIndex(line => /^\s*FINAL,/i.test(line));

  if (finalIndex === -1) {
    config.rules.push(rule);
  } else {
    config.rules.splice(finalIndex, 0, rule);
  }

  return config;
};

4.4 删除匹配的规则

用 filter 返回保留项。下面示例只删除指定域名的规则；其他规则和注释仍会保留。

module.exports = (config) => {
  config.rules = config.rules.filter(line =>
    !line.startsWith('DOMAIN-SUFFIX,old.example,')
  );
  return config;
};

4.5 替换一条规则

module.exports = (config) => {
  config.rules = config.rules.map(line =>
    line === 'DOMAIN-SUFFIX,example.com,旧策略'
      ? 'DOMAIN-SUFFIX,example.com,新策略'
      : line
  );
  return config;
};

4.6 避免重复添加

module.exports = (config) => {
  const rule = 'DOMAIN-SUFFIX,example.org,DIRECT';
  if (!config.rules.includes(rule)) config.rules.unshift(rule);
  return config;
};

4.7 新增 [Host] 主机映射

上游没有 [Host] 分节时，可以先创建它再添加映射。左侧填写要匹配的主机名，右侧填写要映射到的 IP。

module.exports = (config) => {
  config['Host'] ||= [];
  config['Host'].push('nas.example = 203.0.113.10');
  return config;
};

5. 修改其他分节

每个分节都是字符串行数组。示例：为 [General] 添加一个键值项，或创建一个原来不存在的分节。

module.exports = (config) => {
  config['General'] ||= [];
  config['General'] = config['General'].filter(
    line => !/^dns-server\s*=/i.test(line)
  );
  config['General'].push('dns-server = 223.5.5.5');

  config['URL Rewrite'] ||= [];
  config['URL Rewrite'].push(
    '^https?://example\\.com https://www.example.com 302'
  );

  return config;
};

删除整个分节可用 delete config['URL Rewrite']。如果只是读取而不修改某个分节，原始分节内容会原样保留。

6. 保留内容与输出规则

  • 服务会保留没有被脚本改动的分节原文，包括分节内注释、内部空行和原有行顺序。
  • 如果脚本修改某个分节，该分节会按脚本返回的行数组重写；数组中的空行会过滤，注释可照常保留。
  • 最终配置中相邻的分节标题之间统一保留一个空行。
  • 一项数组元素对应一行，不能包含换行符。分节名也不能包含方括号或换行符。
  • 输入里原有的 #!MANAGED-CONFIG 会被服务替换为指向本服务的托管链接。
  • 脚本若创建新的分节，服务会把它追加到配置末尾；新建 Rule 分节同样适用。
  • 同名重复分节会聚合给脚本；如果修改了该分节，输出会合并到第一个同名分节位置。

7. 限制、失败与排查

  • 脚本只能同步执行；不要使用 async、Promise、网络请求、定时器或文件操作。
  • 每段脚本最长运行 500 毫秒。脚本名称最多 100 字符，代码最多 100000 字符。
  • 脚本必须返回配置对象；分节内容必须是字符串数组。
  • 出错时，本次转换会整体失败，不会把部分转换结果发布出去。如果已有成功结果，服务返回上次成功的完整配置；管理页会显示错误。
  • JavaScript 脚本由管理员提供，应视为受信任代码。运行时使用的 Node vm 不构成安全隔离边界；不要粘贴来源不明的脚本。
规则顺序会影响行为。尤其要检查规则与 FINAL 的相对位置。脚本保存后，可在管理页点击“立即拉取并转换”，再查看“上次成功配置”核对最终内容。

8. 在管理页中添加脚本

  1. 在“转换脚本”区域点击“新增脚本”。
  2. 填写脚本名称，将模板替换为所需代码，确认“启用”已勾选。
  3. 保存后使用上下箭头调整执行顺序；可以编辑、禁用或删除脚本。
  4. 点击“立即拉取并转换”。成功后打开“查看上次成功配置”，检查规则、分节和托管链接。

若转换失败，管理页的状态和错误信息会指出具体脚本及错误原因。修正后再次刷新即可。
